# v0.52 — ограничение памяти и диагностика вылетов

Пользователь сообщил о вылете после некоторого времени игры. Logcat/tombstone и сценарий вылета не предоставлены; точная причина на устройстве НЕ подтверждена. Изменения ниже устраняют выявленные в исходниках опасные пути, а не объявляют пользовательский сбой воспроизведённым.

## Физика
- Поиск соседей больше не создаёт произвольное количество ячеек из-за большой скорости/длинной swept AABB. Максимум 64 записи сетки на тело. Для больших диапазонов — консервативный список всех возможных пар; столкновения не отбрасываются.
- Пары дедуплицируются битовой матрицей до заполнения списков, а не после многократного выделения памяти. Для N тел сохраняется не больше N*(N-1)/2 уникальных пар.
- Сетка больше не сводит все объекты за координатой 256 м к одной пограничной ячейке. Диапазон учитывает текущую большую карту.
- До пространственных запросов и после решения контактов проверяются скорости/углы/поля сортировки: NaN/Inf заменяются безопасными значениями; аномальные линейные скорости ограничены 100 м/с, вращение 30 рад/с. Обычные скорости грави-пушки и дрона ниже этих пределов. Тела с нечисловой позицией удаляются штатным способом.
- Порядок сортировки определён даже при нечисловых исходных полях, чтобы не нарушать требования std::sort.

## Графический буфер
Динамическая геометрия использует один растущий VBO с обновлением glBufferSubData, вместо переопределения хранилища glBufferData при каждом обычном/FPV/ghost-проходе. Это снижает частоту выделения памяти драйвером; тест запуска/производительности конкретного GPU ещё необходим.

Для одинаковых исходных изображений и режимов UV-wrap теперь используется общее GPU-хранилище текстуры. В военном городе 136 материалов требуют 8 уникальных хранилищ, а не 136 загрузок (включая белые заглушки). Цвет/прозрачность/шероховатость остаются состоянием каждого материала. Общие texture ID удаляются ровно один раз. Регрессионный тест проверяет и объединение общих изображений, и раздельное хранение при разных wrap-режимах.

## Отчёт на телефоне
После повторного запуска: **Пауза → Отчёт о вылете → Скопировать**. Android ApplicationExitInfo (minSdk 30) показывает до трёх завершений: причину, signal/status, описание, PSS/RSS; отчёт также содержит модель устройства, версию Android, объём RAM. Последнее завершение может быть обычным закрытием, поэтому показываются три. Подготовка выполняется в фоне. Если ОС не сохранила сведения, отчёт прямо это сообщает. Для ANR читаются максимум 8000 байт трассы; бинарные native tombstones не выводятся как текст. Отчёт никуда автоматически не отправляется. Для точного анализа native stack всё ещё может понадобиться adb logcat/bugreport.

## Проверки
`broadphase_safety_test.cpp` с ASan/UBSan: 500 экстремально быстрых тел, плотные скопления, уникальность пар, границы памяти сетки, далеко разнесённые объекты, восстановление NaN/Inf. Прежние физические/FPV/камера/каталог-тесты и сборка APK остаются в CI.

Карта, модели, каталог и новые функции v0.51 сохранены, изменения зеркалируются в game-source. Проверки на хосте и сборка не доказывают устранение конкретного вылета на телефоне; требуется повторный запуск пользователем и отчёт при повторении.
